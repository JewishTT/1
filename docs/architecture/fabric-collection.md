# Global Collection Fabric — Data-plane, Topics, Feedback, Phasing

> Generated by `platform_model/narrative.py` from the tree. Do not edit by hand; run `python -m platform_model.build`.

The collection fabric extends the closed loop. This doc records the implemented data-plane pieces, the compose phasing, and the feedback wiring.

## 1. Data plane

Collection never writes blobs to the event bus (I-5). Raw bytes are content-addressed in the object store; the bus carries refs only.

| Piece | Implementation | Contract |
| --- | --- | --- |
| Content-addressed gate | `ObservationGate.ingest` — sha256 → `s3://…/raw/{tenant}/{ym}/{sha}` with dedup | R-08 `created`/`changed`/`unchanged`/`duplicate`; I-1 immutable after gate |
| Re-observation path | `reobservation.etag_equal` (weak/strong ETag) short-circuits a same-URI fetch | T101 |
| WARC archival | `build_warc`/`lint_warc`/`validate_warc` + browser-leftover capture | T106/T107 |
| WARC range adapter | `adapt_warc` resolves `s3://…?offset=&length=` byte ranges | T093 |
| Bulk historical | CC index replay (`DiscoveryReplay`) + Wayback CDX backfill | T108/T121/T122 |
| Frontier | Postgres `frontier_items` — authoritative (R-02), partition-aware | R-02 |

## 2. Topic taxonomy

Canonical event types map one-to-one to lanes (`apps/shared/events/topics.py`): 99 event types → 29 lanes + `events.dlq` / `events.quarantine`. Acquisition emits `acquisition.{assigned,request,outcome,completed,failed}`; observations map to `observation.{created,changed,unchanged,duplicate}`; feedback closes the loop via `feedback.{generated,source,entity,system}`. Consumers are idempotent on `event_id`/`observation_id`/`task_id`.

## 3. Feedback loops

1. **Recrawl loop**: post-TDA findings produce `feedback.generated`, seeding new frontier items; the scheduler's verdict mix (dispatch/defer/reject) throttles unbounded growth.
2. **Re-observation loop**: ETag/`previous_digest` at the gate prevents re-parse of unchanged content (SC-006).
3. **Region loop**: `RegionBackpressure` (GO/THROTTLE/HALT) gates the dispatcher per region.

## 4. Phased deployment

Compose profiles (`apps/deploy/docker-compose.yml`) gate the stack by phase so the smallest runnable plane is `core`:

| Profile | Services |
| --- | --- |
| `analytics` | clickhouse, neo4j, opensearch |
| `collectors` | browsertrix |
| `core` | minio, minio-init, postgres, redis, redpanda, searxng, temporal |
| `legacy-kafka` | kafka, schema-registry |
| `streaming` | flink-jobmanager, flink-taskmanager, nessie, redpanda, redpanda-console |

```bash
docker compose -f apps/deploy/docker-compose.yml \
  --profile core --profile analytics up -d
```

Multi-region rollout/storage-topology details stay in [multi-region.md](./multi-region.md).
