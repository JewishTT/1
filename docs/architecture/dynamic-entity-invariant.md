# Dynamic Entity Invariant — the atomic entity as a graph-invariant

## The ruling in one paragraph

Exactly two kinds of graph objects exist. A **dynamic invariant** (person, company, site, channel, event) is the center of analysis — a *relational function of its append-only life-stream*; it has temporality (windowed lifecycle), versions and topology, and it changes only when new events arrive. A **static object** (document, photo, conversation) is a content-addressed, immutable evidence leaf that carries no own dynamics; invariants reach it only through typed links. Identity comes exclusively from admission/resolution (I-6); the invariant never decides identity.

## What every invariant contains (and what it does not)

| Block | Contains | Why it belongs here |
| --- | --- | --- |
| Identity | `entity_id`, genesis anchor `evt-<record_hash>`, type label, revision | Stable reference across re-versioning |
| Lifecycle | Ordered epoch-aligned window slices: state (NASCENT/GROWING/STABLE/DECAYING/DORMANT), event counts, cadence, `burstiness`, first/last seen | The temporal series itself; gaps are explicit DORMANT, never interpolated |
| Topology | Neighbor signature, per-window weighted adjacency, structural TDA proxies | The ego-star an analyst sees; structural-only (I-6) and rebuildable |
| Evidence | Observation count, `obs-…` anchors, content digests, assertion ids | Traceability to raw evidence without moving bytes (I-1/I-5) |
| Provenance | tenant, `stream_head`, source hashes, builder/schema, content-addressed event id | Rebuildability proof (I-12) |
| Links | `SO-…` typed refs to static objects | The ONLY way to point at documents/photos/conversations |

Never inside the invariant: raw content, co-mention facts (N-ary hyperedges — `domain.hypergraph`), evidence-dependent attribute values, and the full relational graph.

## Determinism & time

- Windows are epoch-aligned, half-open `[start, end)`.
- `from_entity_stream` sorts by `(ts, sequence, stream_hash)`, dedups exact duplicates (I-11); the same event set in any order replays to a byte-identical `integrity_digest` (I-12).
- Empty streams are rejected; empty windows are DORMANT; missing numbers are `None` or `0.0` — never fabricated (I-3).

## TDA readiness

`to_tda_input` emits the documented adjacency shape without importing projection code; `to_multiplex` emits lossless per-window layers aligned 1:1 with lifecycle slices. L3 computes persistence/features per window and stores **feature time series** — never "a TDA graph".
