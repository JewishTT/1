# ADR-0013: Entity resolution

Status: Accepted
Date: 2026-09-07

## Context

Mentions must be fused into entities/candidates without conflating distinct
real-world referents. Identity must come only from resolution (I-6), with
attributable reasons for every merge.

## Decision

Multi-strategy entity resolution: **blocking** (T082, multi-key, no O(N²)) →
**pairwise scoring** (T035, raw_pair_score + reasons) → **collective/graph-aware
resolution** (T083, propagation + re-score until convergence) with temporal
consistency and retraction (T084).

## Rationale

- Candidate pairs are generated by deterministic, explainable blocking, not
  opaque similarity — avoids O(N²) and keeps behavior auditable.
- Pairwise + collective scores are surfaced with reasons (SC-011), no magic.
- Temporal policies (single/multi/interval/append-only/supersedable/
  contradictory, FR-016) govern assertion state transitions.
- Identity is never stored as transport data; it is produced by this layer (I-6).

## Consequences

- Merge decisions must be reproducible; scoring versions must be tracked.
- False merges/splits are measured by the knowledge-quality harness (T085) and
  drive calibration (T086).
- Resolution defines identity, so its correctness is a top-level quality gate.
